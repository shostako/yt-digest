# 2026-10 作業ログ

## 2026-10-22 Next.js 15.5.28 への更新（RCE 対策）

### 実施内容
- frontend の Next.js を 14.2.0 → 15.5.28、React を 18.3 → 19.3 に上げた（ブランチ `chore/next15-security`）
- 目的は GHSA-2xp9-vwfh-vxw4（`/_next/image` 経由の未認証 RCE、AVIF）。修正版は 15.5.24 以上か 16.3.3 以上。npm audit が勧める 14.2.35 では直らない
- `next` 15.5.28 は postcss 8.4.31 を固定で持っていて、postcss の high が残る。`overrides` で postcss を ^8.5.31 にした（Next 16.4.2 は 8.5.23 を使っているので 8.5 系で動く前提）
- `npm audit fix` で nanoid と source-map-js を上げた
- `next.config.js` に `outputFileTracingRoot: __dirname` を足した。手元では親ディレクトリ（~/ClaudeCode）の package-lock.json を拾ってワークスペースのルートを取り違える警告が出るため

### 結果
- npm audit: 前 4 件（critical 1・high 3）→ 後 0 件（`--omit=dev` も 0 件）
- `tsc --noEmit`、`npm run build`、`next start` で `/` が 200
- Playwright でバックエンドを差し替え、URL 入力 → 解説の表示（react-markdown の見出し・箇条書き）、バックエンド停止時のエラー表示、テーマ切り替えが動くことを確かめた

### 技術的発見
- コードの変更は要らなかった。ページはクライアントコンポーネント 1 枚で、`cookies()` / `headers()` / `params` / route handler を使っていないため、Next 15 の非同期 API・キャッシュ既定の変更が当たらない
- App Router だけのアプリは Next 15 で React 19 が必須（codemod も React 18 に残す選択を出さない）
- 手元の Chromium（Playwright）から `localhost:8000` への fetch は、待ち受けが無いのに失敗せずに止まった。検証では `page.route` で API を差し替えた
